# 周会报告 II：LoRA vs 全量微调公平对比（90% vs 80%）

> 日期：2026-10-09 ｜ 任务：LIBERO-10 ｜ 口径与报告 I 完全一致（固定噪声 + 100 条档 + exec=15）

## 一、一句话结论

在**同起点、同数据、同训练预算、同 lr 计划**下，**1.41% 参数的 LoRA（rank32）取得 80.0%**，显著低于全量的 90.0%（逐条配对 **Δ=−10.0 pt，p=0.0414**）——低秩便利贴装得下大部分专攻能力，但长程精细任务的"最后 10 分"需要全量容量。

## 二、实验设计（严格单变量）

$\text{pi05\_ckpt\_6000}(30\%) \xrightarrow[\text{libero\_10}]{10000\ \text{步},\ \text{bs32},\ \text{lr}\ 1.76e\text{-}5\to1e\text{-}6} \begin{cases} \text{全量：更新 } 4.20\text{B 参数} \to 90.0\% \\ \text{LoRA：仅更新 } 59.06\text{M 参数（1.41\%）} \to 80.0\% \end{cases}$

| 配置项             | 全量组                       | LoRA 组                                                 | 是否对齐   |
| --------------- | ------------------------- | ------------------------------------------------------ | ------ |
| 起点              | `long/ckpt_6000`          | 同（硬链同 inode）                                           | ✅      |
| 数据 / 步数 / batch | libero_10 / 10000 / 32    | 相同                                                     | ✅      |
| lr 计划           | 热重启 1.76e-5 → 1e-6 cosine | 相同                                                     | ✅      |
| **更新方式**        | 全部参数                      | **rank32/α32，attn q/k/v/o + FFN gate/up/down（333 模块）** | ← 唯一变量 |
| 评测              | exec=15，100 条，固定噪声        | 相同                                                     | ✅      |

## 三、主结果

| 组        |             可训练参数 |       成功率 | 95% CI       |    训练墙钟 |            存档/档 |
| -------- | ----------------: | --------: | ------------ | ------: | --------------: |
| 全量       |       4.20B（100%） | **90.0%** | [82.6, 94.5] |  23.2 h |          18.7 G |
| **LoRA** | **59.06M（1.41%）** | **80.0%** | [71.1, 86.6] | 29.0 h* | **0.7 G（27×↓）** |

\* LoRA 更慢：附加分支前向/反向是纯增量计算 + 小 GEMM 启动开销 + GPU2 与他人任务共享，非方法本质劣势。

**配对检验**：翻面（全量败 LoRA 成）= 5，（全量成 LoRA 败）= 15 ⇒ **p = 0.0414**。  
**收益比**：起点 30% → 全量 +60 pt、LoRA +50 pt ⇒ **LoRA 拿到约 5/6 的专攻收益**。

## 四、按任务分层：差距集中且性质明确

| task          |       全量 |     LoRA | 差距性质                    |
| ------------- | -------: | -------: | ----------------------- |
| t0–t3, t6, t7 |  9–10/10 |  9–10/10 | 打平——易任务低秩足够             |
| **t4**        |     8/10 | **5/10** | 长程多物体，容量敏感              |
| **t5**        |     9/10 | **4/10** | 差距最大（−5）                |
| t9            |    10/10 |     8/10 | 略差                      |
| **t8**        | **5/10** | **6/10** | **LoRA 反超**（全量组唯一失败集中点） |

两条推论（标注为判断）：

1. **缺的 10 pt 不是均匀退化**，集中在长程、多物体、精细放置类任务——低秩约束下"易任务学得会，精细修正学不满"。若只关心简单任务，LoRA 是零损失替代。
2. **t8 反超与执行长度消融中 t8 的特异行为相互印证**（四个执行长度下 t8 均异常），提示 t8 的失败与更新方式/容量存在交互，值得单独归因——这可能成为一条独立研究线。

## 五、实现要点（零改仓库，全部 shim 化）

1. **注入**：训练侧 `sitecustomize` patch `_build_optimizer`（该钩子在 optimizer 创建**之前**执行，保证优化器只收 LoRA 参数）——`peft.get_peft_model(rank=32, alpha=32, dropout=0.05)`，实测 `trainable=59.06M/4202M=1.41%`
2. **保存**：patch `_save_checkpoint` 为 adapter-only（472 MB adapter + 236 MB optimizer state）——不 patch 会在首个保存间隔崩溃（PeftModel 的 state_dict 与框架全量保存器结构不兼容）
3. **合并**：评测前纯张量合并 $W \mathrel{+}= \frac{\alpha}{r}BA$（不建模型，秒级），输出 813 裸键直接进现有评测管线
   - ⚠️ 坑：adapter 键带 `base_model.model.module.{model,pi05}.` **双前缀别名**（同一权重经两个属性路径各存一遍），必须剥前缀去重后合并（333 模块）；校验 = 328 目标张量全变化 + 485 非目标（bias/LN/动作投影头）不动
4. **对齐社区经验**：α/r=1（openpi 官方 300M action expert 与 verl-vla 同款）；EMA 不使用（openpi 明确经验）

## 六、成本-收益权衡表（选型决策用）

| 维度      | 全量        | LoRA                   | 谁赢             |
| ------- | --------- | ---------------------- | -------------- |
| 成功率上限   | 90.0%     | 80.0%                  | 全量（+10 pt）     |
| 训练显存峰值  | 37 G      | ~30 G                  | LoRA（可在更小的卡上跑） |
| 存档体积    | 18.7 G/档  | **0.7 G/档**            | LoRA（27×）      |
| 多任务切换   | 每任务一套完整权重 | **每任务一个 MB 级 adapter** | LoRA（场景决定性优势）  |
| 训练速度    | 8.35 s/步  | 10.2 s/步               | 全量（快 23%）      |
| 继续微调自由度 | 无约束       | 受低秩约束                  | 全量             |

**选型结论**：追求单任务极致（≥90%）→ 全量；多任务部署 / 存储受限 / 快速适配新任务 → LoRA（接受 −10 pt）。
